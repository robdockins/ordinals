# Statement review: Rocq and Lean side by side

This file is generated by `scripts/statement_review.py`; edit
`scripts/statement_review_preamble.md` to change this introduction.

It lists every Rocq `Theorem`, together with the other headline declarations
named in the porting plan:
- the reflection theorems and the `*_has_enough_notations` theorems;
- the order-type theorems (`VF_ε₀`, `VF_Γ₀`, `VF_SAO`, `VF_LAO`, `VF_SVO`,
  `VF_LVO`);
- the reverse-mathematics lemmas of `Classical.v` (`*_EM`, `*_WEM`);
- `cantor_decomposition_is_classical*`, `KnuthUp_epsilon`, `Γ₀_least`,
  `Γ_enumerates`, `wf_ord_lt_nat_omega`;
- the Goodstein theorems.

Both statements are printed by the provers themselves:
- **Rocq:** `Check` on the compiled development. Section hypotheses such as
  `EM` therefore appear exactly as Rocq discharges them when the section
  closes.
- **Lean:** `#check` on the declaration that the porting map names.

## Result

Every statement was compared by hand. **No mathematical discrepancy was
found.** Every hypothesis is present, including `complete`, `EM`, `HC` and
`normal_function`, and every conclusion matches. The systematic differences
are presentational:

- **Notation.** `ord_lt`, `ord_le` and `ord_eq` print as `<`, `≤` and `≈`;
  `Ord` is `Ordinal`; `addOrd`, `mulOrd`, `expOrd` and `naddOrd` are `+`, `*`,
  `^` and `♯`. Rocq's `succOrd 0` is Lean's `1`, which is definitionally
  `succ 0`.
- **Universes.** Rocq's `Ord` lives in one fixed universe; Lean's
  `Ordinal.{u}` is universe-polymorphic. The notation systems use
  `Ordinal.{0}`. The bound type in `WellFounded.lex_exp_eq` is a `Set` in
  Rocq and any `Type` in Lean.
- **Binders.** Some arguments that Rocq makes explicit are implicit in Lean,
  where they are inferable. The order of arguments and hypotheses is
  otherwise preserved, with `EM`/`HC` first.
- **Numbers.** Rocq's `N` and `positive` are Lean's `Nat`, for Goodstein's
  sequences and for `natOrdSize`, which is `ofNat`.
- **Informative types.** `{A} + {B}` is `A ⊕' B` (`PSum`), and
  `{P} + {~P}` is `Decidable P`.
- **Unique existence.** Rocq's `exists! a, P a` is written out as
  `∃ a, P a ∧ ∀ a', P a' → a' = a`.
- **The `PROP` shape.** The reflection framework's `PROP` shape lifts
  propositions into a universe, so a relation such as `<` appears as
  `fun x y => { down := x < y }`.
- **Canonical structures.** Rocq states some theorems about
  `ordCarrier VF` with the size function `sz`. Lean states them about the
  syntax type itself, with `sz` from its `Sized` instance; the two are the
  same.
- **Abbreviations.** In the Ackermann notations, `veblen (T n)` abbreviates
  `veblen (ackermann_tower_fin (addOrd 1) n)` (`ATowerFin`) and
  `veblen (ackermann_tower (addOrd 1) n)` (`ATower`); `T` is an `abbrev`.
- **Proof arguments.** Well-foundedness proofs inside `wf_ord` are elided as
  `⋯`. The choice of proof is irrelevant (`wf_ord_proof_irr`); for example,
  Rocq's `Wf_nat.lt_wf` is Lean's `nat_lt_wf`.
- **Standard-library relations.** Rocq's `inclusion`, `clos_refl_trans`,
  `clos_trans`, `le_AsB`, `symprod`, `slexprod`, `lexprod`, `lex_exp` and
  `list_ext` are re-defined in `Prelude/Relations` with the same
  constructors, since Lean core has no counterparts. `inclusion A R₁ R₂` is
  unfolded to `∀ x y, R₁ x y → R₂ x y`.
- **Choice.** `DependentFunctionalChoice` has the shape of Rocq's
  `ChoiceFacts.DependentFunctionalChoice`, with the domain and the fibres in
  the same universe as the ordinals.
- **A renamed function.** `CF_normalize` (Cantor forms) is
  `CantorForm.toCNF`.
